# Contributing to ArchiveX

First of all, thank you for taking the time to contribute to ArchiveX.

ArchiveX is an open-source project dedicated to preserving academic resources and making them easily accessible to students. Every contribution helps improve the platform.

---

# Code of Conduct

Contributors are expected to:

- Be respectful.
- Be professional.
- Provide constructive feedback.
- Respect differing opinions.
- Focus on improving the project.

Harassment, discrimination, or abusive behavior will not be tolerated.

---

# Getting Started

1. Fork the repository.
2. Clone your fork.
3. Create a new branch.
4. Make your changes.
5. Test your changes.
6. Commit using meaningful commit messages.
7. Push your branch.
8. Open a Pull Request.

---

# Branch Naming

Use descriptive branch names.

Examples:

```
feature/course-search

feature/admin-dashboard

fix/upload-validation

docs/readme-update

refactor/auth-service
```

---

# Commit Message Convention

Examples:

```
feat: add course management

fix: resolve PDF upload bug

docs: update deployment guide

refactor: simplify authentication middleware

style: improve dashboard layout

chore: update dependencies
```

---

# Pull Requests

Before submitting a Pull Request, ensure:

- Code builds successfully.
- Existing functionality is not broken.
- Documentation is updated where necessary.
- New code follows project conventions.

Explain:

- What changed
- Why it changed
- Any limitations

---

# Reporting Issues

Include:

- Description
- Steps to reproduce
- Expected behavior
- Actual behavior
- Screenshots (if applicable)
- Environment information

---

# Feature Requests

Feature requests should include:

- Problem statement
- Proposed solution
- Expected benefits
- Possible drawbacks

---

# Coding Standards

Contributors must follow:

- Coding Guidelines
- Engineering Principles
- Security Policy

These documents define the project's development standards.

---

# Documentation

Documentation is considered part of the project.

When adding or changing functionality:

- Update documentation if necessary.
- Keep examples accurate.
- Keep explanations concise.

---

# Security Issues

Do not publicly disclose security vulnerabilities.

Instead, report them privately to the project maintainer.

---

# Project Philosophy

ArchiveX values:

- Simplicity
- Reliability
- Security
- Maintainability
- Accessibility
- Long-term sustainability

Every contribution should support these principles.

---

# Thank You

Every contribution, whether code, documentation, testing, bug reports, or ideas, helps make ArchiveX a better platform for students.

Thank you for being part of the project.
